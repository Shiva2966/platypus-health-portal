## Document storage spec (W2)
Table `documents`: id (UUID), patient_id, name (required, 1-200), description (optional, <=2000), category, mime_type, size_bytes, sha256, data (BLOB, the actual file bytes in SQLite), source ('patient_uploaded'|'clinician_provided'), uploaded_by_type/id, created_at, updated_at, deleted_at (soft delete), is_private (bool, default true). Allowed: PDF, JPG, PNG, HEIC/HEIF, WEBP, TXT, DOCX (verify by magic bytes, not just extension). Max 15 MB. Reject duplicates by sha256 per patient with a clear message. Per-document options: share/unshare per provider, expiry, private flag, category, edit name/description, delete, download, preview. Nothing shared by default. Files are only served through authorized endpoints (patient owner or staff with valid grant); `Content-Disposition` safe, `X-Content-Type-Options: nosniff`.

## DATABASE RELIABILITY RULES (added by the user's direction; ALL agents follow; W5 enforces)
The app will run as ONE central internet-hosted server with ONE strong database (production = PostgreSQL; local dev = SQLite). Therefore:
- Never hard-code SQLite. `app/db.py` reads `DATABASE_URL` (default `sqlite:///data/app.db`). W5 is AUTHORIZED to edit `app/db.py` for this.
- Write portable SQLAlchemy 2.x only: no SQLite-only SQL/PRAGMA outside db.py; ids are `String(36)` UUIDs; files are `LargeBinary`; timestamps are timezone-aware UTC (`DateTime(timezone=True)`); money is `Numeric(12,2)`, never float; JSON stored as `Text` or SQLAlchemy `JSON`.
- Declare real constraints: foreign keys with explicit `ondelete`, `nullable=False` where required, `CheckConstraint`s for enums/status, `UniqueConstraint`s (e.g. documents (patient_id, sha256) among non-deleted), and indexes on every foreign key and every searched column (names, dates, status).
- Do all multi-step writes (record + audit + notification) in ONE transaction so they commit or roll back together. Never swallow DB errors.
- Large file BLOBs live in a separate table `document_blobs` (document_id PK/FK, data) so list queries never load file bytes (W2: adjust the spec accordingly: `documents` holds metadata only).
- Schema changes go through Alembic migrations once W5 sets them up (`alembic/`); until then `create_all` is acceptable.
